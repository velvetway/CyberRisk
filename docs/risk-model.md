# Модель риска ПТСЗИ

Платформа реализует модель **вероятностно-тактической схемы защиты информации (ПТСЗИ)**.
Источник модели — дипломная работа: схемы и формула в `/Users/velvetway/Downloads/Расчет идеи/`.

Это **единственная** модель риска в системе. Никаких параллельных «legacy» формул
(матрица 5×5, Impact × Likelihood, regulatory factor) больше нет.

## Граф атаки

```
S (источник) ──► ST (угроза) ──► VL (уязвимое звено) ──► DA (деструктивное действие)
                                      ▲
                                     └─ методы противодействия (controls), внедрённые на активе
```

## Формула

$$W_i = \frac{Q_i^{threat} + q_i^{threat} + (1 - Q_i^{reaction})}{3} \cdot Z, \quad W_i \in [0, 1]$$

| Обозначение      | Смысл                          | Диапазон     | Источник данных                                                |
|------------------|--------------------------------|--------------|----------------------------------------------------------------|
| `Q^threat`       | Степень реализации угрозы      | [0, 1]       | `threats.q_threat`                                             |
| `q^threat`       | Степень опасности угрозы       | [0, 1]       | `threats.q_severity`                                           |
| `Q^reaction`     | Степень предотвращения угрозы  | [0, 1]       | доля VL, у которых на активе внедрён хотя бы один control      |
| `Z`              | Коэффициент критичности контура| {0.5, 1.0}   | `assets.is_isolated`                                           |

### Вычисление `Q^reaction`

Для пары *(актив, угроза)*:

1. Берём все VL, связанные с угрозой (`threat_vulnerable_links`).
2. Для каждого VL проверяем, есть ли хотя бы один control из `vulnerability_controls`,
   одновременно внедрённый на активе (`asset_controls`).
3. `Q^reaction = |covered_VL| / |threat_VL|`. Если у угрозы нет VL — возвращается `0`
   (нечего «закрывать» — реакция нулевая).

### Вычисление `Z`

Берём ровно по диплому — два значения:

| Условие                 | Z   |
|-------------------------|-----|
| `assets.is_isolated = TRUE`  | 0.5 |
| `assets.is_isolated = FALSE` | 1.0 |

> Логика: если актив изолирован (один контур), значимость угрозы ослабляется в 2 раза.
> Если актив доступен в обоих контурах — значимость полная.

## Уровни риска

| W                 | Уровень   |
|-------------------|-----------|
| [0.00, 0.25)      | low       |
| [0.25, 0.50)      | medium    |
| [0.50, 0.75)      | high      |
| [0.75, 1.00]      | critical  |

## Поля актива, используемые формулой

Из всей анкеты актива в формуле W участвует **только**:

- `is_isolated` — для `Z`
- множество внедрённых контролей (`asset_controls`) — для `Q^reaction`

`name`, `description`, `asset_type_id`, `owner`, `environment`, `tags` — описательные
метаданные для UI/отчётов, в формулу не входят.

Поля старой модели (`confidentiality`, `integrity`, `availability`,
`business_criticality`, `kii_category`, `data_category`, `protection_level`,
`has_personal_data`, `personal_data_volume`, `has_internet_access`, `type`, `location`)
**удалены** — они не имеют веса в W. См. миграцию `020_drop_legacy_risk_fields`.
